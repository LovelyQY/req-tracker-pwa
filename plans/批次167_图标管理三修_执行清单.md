## 关键事实（已排查确认）

### 问题1：导出 toast 未显示
- **现象**：点「导出全部」后弹出系统下载对话框（文件名/大小/取消|下载），但顶部 toast 提示「已导出 N 个图标…」不出现。
- **根因**：`exportAll()`（`icon-manager.js:103-121`）中 `toast()` 调用在 `a.click()` + `URL.revokeObjectURL()` **之后**（行120）。浏览器触发下载后：
  - 系统下载对话框抢夺焦点/阻断页面 JS 主线程短暂时间；
  - 或 `document.body.removeChild(a)` 导致 reflow，toast 的 show class 未来得及渲染就被 transition 清除。
- **修复**：将 `toast()` 移至 `a.click()` **之前**，确保 toast 先进入显示态再触发下载。

### 问题2：详情代码块底色为黑色
- **现象**：`.code-block` 区域显示深蓝灰背景（#1e293b）+ 白字，用户认为太突兀。
- **根因**：批次164 新增的 `.code-block` CSS（`icon-manager.html:70-73`）使用了深色主题配色：
  ```css
  .code-block{background:#1e293b;color:#e2e8f0;…}
  ```
- **修复**：改回与原 textarea 一致的浅色风格（`background:#f8fafc;color:#334155` + 细边框），保持等宽字体/pre-wrap/可滚动。

### 问题3：customConfirm 弹框显示在页面下方（非居中浮层）⚠️ 根因级别：高
- **现象**：点「批量重置」（应改名「批量恢复」）后，确认框内容出现在页面底部（截图1可见："批量重置"/正文/"取消|全部恢复"），而非居中浮层。与删除操作的弹框表现一致（均非居中）。
- **根因（已确凿）**：**`icon-manager.html` 没有引入 `overlays.css`！**
  - 该页 `<head>` 仅引入 `theme.css`（行12），无 `overlays.css` 引用。
  - `customConfirm()`（`config.js:136`）创建的 overlay 元素 class 为 `cd-overlay`，其完整样式定义在 `overlays.css:101-112`（`position:fixed;inset:0;display:flex;align-items:center;justify-content:center;z-index:1000`）。
  - 缺少此 CSS → `.cd-overlay` 无定位样式 → 变成普通 block 流式元素 → 渲染在 body 末尾（页面底部）。
  - **同理**：单个「恢复默认」的 customConfirm 也受影响（只是列表项的 reset 因 166 修复后走通了，弹框同样在底部而非居中；用户之前反馈"弹框不显示"实际是"弹框在底部被忽略/遮挡"）。
- **修复**：
  1. `icon-manager.html` 的 `<head>` 补引 `overlays.css?v=1.3.65`。
  2. 按钮「批量重置」→「批量恢复」。
  3. `resetAll()` 的 `title` 参数同步改为「批量恢复」。

## 批次167.1：导出 toast 时序修复

**锚点**（`icon-manager.js:103-121` `exportAll()`）：

将 `toast()` 从 `URL.revokeObjectURL(url)` **之后**移至 `a.click()` **之前**：

```javascript
function exportAll() {
    if (typeof RT_PAGE_ICONS === 'undefined') { toast('图标模块未加载'); return; }
    var data = { updatedAt: new Date().toISOString(),
      icons: RT_PAGE_ICONS.list().map(function (it) {
        return { key: it.key, svg: it.svg, source: it.source };
      }) };
    var blob = new Blob([JSON.stringify(data, null, 2)], { type: 'application/json' });
    var url = URL.createObjectURL(blob);
    var a = document.createElement('a');
    a.href = url;
    a.download = 'page-icons-' + Date.now() + '.json';
    document.body.appendChild(a);
    // ★ 先 toast（确保在下载抢焦前已进入显示态）
    toast('已导出 ' + data.icons.length + ' 个图标（在各页面以 44×44 展示）', 'success');
    // ★ 再触发下载
    a.click();
    document.body.removeChild(a);
    URL.revokeObjectURL(url);
}
```

### 验证
- 点「导出全部」→ 顶部先闪现 toast「已导出 19 个图标…」→ 再弹出系统下载对话框

## 批次167.2：详情代码块底色改回浅色

**锚点**（`icon-manager.html:70-73`）：

```css
/* 替换前（深色） */
.code-block{background:#1e293b;color:#e2e8f0;border-radius:10px;padding:14px;overflow:auto;max-height:280px;

  line-height:1.6;white-space:pre-wrap;word-break:break-all}
```

- 长SVG 可横向滚动，长属性自动折行

## 风险与注意
- **167.3 补 overlays.css 是最高优先级修复**：它同时解决 166 遗留的"弹框位置"问题和本次"批量恢复弹框"问题。缺此 CSS 则全页所有 customConfirm 均异常（包括未来新增的任何确认场景）。
- 167.1 toast 时序：某些浏览器（如 Safari）可能在 `a.click()` 后延迟触发下载，toast 与下载对话框可能短暂重叠——属可接受范围（toast 2.5s 后自动消失）。
- 167.2 底色改动纯视觉，不影响功能。
