| 项 | 说明 |
|----|------|
| **目标** | 用户在设置选语言（zh-CN / zh-HK / zh-TW / en / ko / ja）后，**全站所有页面的静态文字、按钮、标题、提示（toast/确认框/空状态）、错误文案，均切换为该语言** |

## 二、i18n 框架设计

在现有 `RT_CONFIG` i18n 骨架上升级：

| 组件 | 设计 |
|------|------|
| **`t(key, vars?)`** | 全局翻译函数：`t('task.title')` → 当前语言字典取值；缺失 key 回退到 `zh-CN`（保证不白屏） |
| **字典加载** | `i18n/{zh-CN,zh-HK,zh-TW,en,ko,ja}.json`，按 `RT_CONFIG.getLang()` 懒加载/内置 |
| **`langchange` 事件** | 语言切换后广播；所有视图监听并**重渲染当前页文案**（不刷新页面） |
| **启动时应用** | `app.js` 初始化即 `applyLang(savedLang)`：设置 `<html lang>`、加载字典、首次渲染 |
| **动态文案** | 含变量的串用 `t('x', {n:3})` 占位替换（如"共 {n} 条"） |

**接入方式（两种并用）**：
- **静态文案**：HTML 元素加 `data-i18n="key"`，`applyLang` 时批量填充 `textContent`/`placeholder`。
- **动态/JS 生成文案**：调用处改为 `t('key')`（含 `toast(t('...'))`、确认框、`RT_USERS` 错误提示等）。

## 三、覆盖范围（必须全量，否则"切换"不完整）

| 类别 | 范围 |
|------|------|
| 页面结构 | 所有 HTML 的标题、按钮、标签、占位符、空状态文案 |
| 提示系统 | `toast()` 所有消息、`customConfirm()` 文案、表单校验错误 |
| 动态列表 | 状态名/类型名（如"待开发/已上线"）、统计标签、菜单项 |
| 设置中心 | 174-178 全部子视图文案（含新增的 6 语言/主题色/通知等） |
| 日历/考勤/首页 | 180-184 全部新增文案（打卡、节假日、请假、统计报表） |
| 帮助/反馈 | 帮助文档（若存 `help_*.json`）、反馈表单与状态 |
| 错误/异常 | 网络/存储/同步失败提示 |

> 这是本项目**最大单项工程**：需扫描全部 `*.html` + `*.js`，逐条抽取中文为 key。建议用脚本辅助提取（正则扫描中文串生成候选 key），人工校译。

## 四、字典结构

```jsonc
// i18n/zh-CN.json（基准，所有 key 的来源）
{
  "app.title": "需求任务追踪",
  "tab.task": "任务",
  "tab.todo": "待办",
  "tab.calendar": "日历",
  "tab.feedback": "反馈",
  "common.save": "保存",
  "common.cancel": "取消",
  "toast.saved": "已保存",
  "task.status.dev": "待开发",
  "calendar.clockIn": "上班打卡",
  "feedback.submitted": "已提交，感谢反馈"
  // ...全站所有串
}
```
- 6 份字典 key 集合必须**一致**（以 zh-CN 为 single source of truth）。
- zh-HK / zh-TW 与 zh-CN 主要差异在**用词与繁简**（如"账户/帳戶"、"软件/軟體"）；en/ko/ja 为全译。

## 六、与 CloudBase 的关系

- 语言**偏好**（`RT_CONFIG.getLang()` 的值）存 `user_settings`，经 `RT_SYNC` 跨设备漫游（见 CloudBase 方案第六节）。
- **字典文件本身**为静态资源（随发版打包），不走云端；仅偏好漫游。

## 七、风险与注意

- **最大单项工程**：全站文案抽取 + 6 语言翻译，工作量远超单个 UI 批次，建议独立排期、可分步上线（先 zh-CN/HK/TW，再 en/ko/ja）。
- **回退机制必做**：任何 key 缺失回退 zh-CN，避免切语言后白屏/空串。
- **toast/确认框易漏**：提示系统散落在各 `toast()` 调用点，必须全量替换，否则"提示不切换"会被用户一眼看出。
- **动态数据不翻译**：业务数据（用户名、需求标题、反馈内容）是用户录入内容，**不翻译**；仅 UI 框架文案翻译。
- **dict key 一致性**：6 份字典 key 必须对齐，新增文案须同步 6 份（可用脚本校验缺失 key）。
- **与批次176 协同**：176 只负责"选择器+持久化+触发 langchange"；本批消费该事件做全站重渲染，二者解耦。
- **发版注意**：新增 `i18n/*.json` 需在 `release.sh` 登记引用（参见批次169 教训），避免漂移自检失败。
