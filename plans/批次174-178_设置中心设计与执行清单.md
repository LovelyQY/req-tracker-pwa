## 二、架构方案

1. **hub 框架**：改造 `settings.html` 为「landing 分组列表 + 隐藏子视图」单文件多视图，路由驱动沿用 `storage-backup` 范式：
   - `MODULES`/`GROUPS` 定义 `{key, name, desc, hash, icon}`；行点击 `location.hash='#'+hash`；`hashchange` → 切 `hidden`。
   - landing 行左侧用 `page-icons.js` 图标（需新增），右侧 `info-arrow` 箭头。
2. **现有页面整合**：
   - **账号分组（资料/安全/设备）= 内嵌 hash 子视图**（在 settings.html 内渲染，复用 `RT_USERS` API；后端就绪后读写 CloudBase `users`/`login_logs`）；原 `profile.html`/`security.html` 保留为抽屉独立入口不删。
   - **通用/帮助 = 纯前端配置子视图**，全部内嵌在 settings.html。
3. **抽屉整合**：保留「个人信息」「账号与安全」「存储与备份」「设置」四个入口不变；设置中心 hub 内通过 hash 子视图承载上述子项。
4. **后端依赖**：云同步、登录设备、账号资料/安全的跨设备真实化，依赖"阶段0·CloudBase 后端准备"先行完成（见第八节）。

## 六、CloudBase 后端版能力（原"受限能力"修订）

引入 CloudBase 后端后，原"纯静态无后端"的受限前提被打破。各项真实度如下：

| 设置项 | 后端版能力 | 说明 |
|--------|-----------|------|
| 云同步 | ✅ 完全真实 | `RT_SYNC` 引擎 + `sync_logs` |
| 登录设备 | ✅ 完全真实 | `login_logs` 历史 + 登出其他设备 |
| 账号资料 / 安全 | ✅ 真实 | `users` 集合，跨设备一致 |
| 深色 / 主题色 / 语言 | ✅ 可跨设备漫游 | 偏好存 `user_settings` |
| 系统权限 | ⚠️ 半真 | 相机/存储仍是浏览器 Web API；可存"已授予状态"漫游 |
| 下载地址 | ⚠️ 半真 | 浏览器不能设 OS 目录；存默认文件名/位置标签漫游 |
| 通知（真实推送） | ❓ 最重 | 开关配置可真；真实推送需自建 Web Push（VAPID + 云函数） |

> 仍受浏览器/平台硬限制的项：系统权限授予、OS 下载目录、无服务端则无真实推送。这些无法靠 CloudBase 消除，只能做状态漫游与 UI 引导。

## 八、风险与注意

- **阶段0 优先级最高**：hub 框架（174）可先做，但云同步/登录设备/资料跨设备真实化必须等后端就绪。

- **深色模式**：需全站变量化（base.css 已集中变量，改动可控），`theme-color` meta 同步。
- **主题色变量化**：散落硬编码蓝必须收敛到 `var(--primary)`，否则换色不彻底（当前默认蓝作为预设）。
- **6 语言**：本批（176）仅做选择器 UI；**全站词条字典 + 所有页面文案 rewire 是本项目最大单项工程，由独立批次185 负责**（建议先 zh-CN 基准 + zh-HK/zh-TW，再 en/ko/ja）。
- **图标**：新增 key 后需在 release.sh 登记引用（参见批次169 教训，`STYLES_SPLIT_PAGES`/页面 `patch_ver` 同步），避免发版漂移自检失败。
- **认证桥接先行**：无 `uid` 则安全规则不生效，同步无从谈起。
- **软删除必做**：硬删无法同步，历史会"复活"。
