## 0. 总览
将散落在各 HTML 内联脚本中的重复工具/辅助函数抽取到共享模块，消除 DRY 违规。

## 1. 现象
- 同一工具函数在多个页面各自定义，版本漂移风险高。

## 2. 根因定位（实测）
- 内联 `function $(id){...}` 定义于 **11 个 HTML**（about/changelog/company/department/dictionary/position/project-version/project/user/security/login-classic）。
- 辅助函数重复文件数：`showErr`×9 / `setErr`×9 / `clearErr`×10 / `fmtTime`×8 / `applyGuard`×7 / `updateCounter`×8 / `openSheet`×8 / `closeSheet`×9 / `openConfirm`×8 / `closeConfirm`×8。
- 其中 `$`、`fmtDate`/`fmtDateTime` 在 `app.js`/`config.js` 已有定义，内联版纯属重复。

## 3. 修改方案
- 新建（或并入既有）共享模块 `ui-utils.js`，集中导出 `$` / `showErr` / `setErr` / `clearErr` / `fmtTime` / `applyGuard` / `updateCounter` / `openSheet` / `closeSheet` / `openConfirm` / `closeConfirm`。
- 各 HTML 删除本地定义，改为引用全局（在页面 `<script>` 前以 `<script src="ui-utils.js?v=...">` 引入）。
- 保留调用签名；`$` 全仓仅保留一份定义。
- 在 `release.sh` 注册 `ui-utils.js`。

## 4. 验收
- [ ] 上述函数在各 HTML 内联脚本中不再各自定义。
- [ ] 表单校验、弹窗（sheet/confirm）、toast 在各页面行为不变。
- [ ] 全仓 `function $(id)` 仅定义一次；`node --check` 各引用文件通过。
