## 一、主页 TAB 栏重构（结构先行）

现有 `index.html` TAB 栏为 `任务 / 代办`（app.js:73-74，`switchView` 按 `data-view` 通用切换）。本次扩展为 **5 个 TAB**，顺序与默认落地如下：

| 顺序 | TAB | data-view | 说明 |
|------|-----|-----------|------|
| 1 | **首页** | `home` | **新增·默认落地页**（仪表盘，数据总览，非待办列表） |
| 2 | 任务 | `task` | 现有任务列表（保持不变） |
| 3 | 待办 | `todo` | 现有待办（"代办"笔误保留） |
| 4 | **日历** | `calendar` | **新增**（日历 + 上下班考勤 + 节假日 + 请假 + 当日详情） |
| 5 | 反馈 | `feedback` | 新增（见设置中心 批次179） |

> 说明：用户要求"在待办和反馈之间加日历 TAB" → 即 任务/待办/**日历**/反馈；"设计一个首页" 单独作为默认落地 → 置于最左。日历 TAB 名称默认用「日历」，因其主视觉为月历；若强调考勤可改名「考勤」，本方案以「日历」为准、页内标题「日历 / 考勤」。

切换逻辑**无需改** `switchView(view)`（app.js:893，按 `data-view` 通用切换），仅需在 `index.html` 补按钮 + 对应 `<div class="view" id="view-xxx">` 容器，并在 `app.js` 补各视图渲染函数（如 `renderHome()` / `renderCalendar()` / `renderFeedbackTab()`）。

## 三、数据模型（本地优先，阶段0 后同步 CloudBase）

考勤/请假属个人高频写数据，采用**本地 IndexedDB 优先**（沿用现有纯静态架构），待 `CloudBase同步架构方案` 的"阶段0"就绪后，经 `RT_SYNC` 同步到云端，实现跨设备。

| 存储 | 结构 | 说明 |
|------|------|------|
| `attendance` (IDB/CloudBase) | `{_owner, date:'YYYY-MM-DD', clockIn:ts, clockOut:ts, workMinutes, status:'normal'|'late'|'early'|'absent'|'leave'|'rest'}` | 每日打卡记录，一天一条 |
| `leave` | `{_owner, date, startHour, endHour, durationMin, reason, type:'事假'|'病假'|'年假'|'其他'}` | 按小时请假 |
| `day_override` | `{date, isWork:boolean}` | 手动调整当天上班/休息（覆盖节假日推断） |
| `holidays` | `{date, type:'holiday'|'makeup'|'work'|'rest', name}` | 年度节假日表（法定假日 / 调休补班 / 补假） |
| 复用 | `requirements`/`todos`/`feedback` | 当日映射用 `createdAt`（见第五节） |

**节假日数据来源**：纯静态 PWA 无构建步骤，采用**年度静态 JSON**（如 `holidays-2026.json`，含法定假日与调休补班/补假，每年手动更新一份）+ 阶段0 后 CloudBase `holidays` 集合可覆盖。推断规则：有 `holidays` 记录以记录为准；否则周末=休息、工作日=上班。

## 四、工时计算规则（8:30–17:30 灵活计算）

> 用户原话："工时规定的早上8点半与17点30，要根据打卡时间灵活计算。"

- **标准工时窗**：08:30–17:30；**午休 12:00–13:30（1.5h）默认不计入工时**（可在设置中调整）。
- **有效出勤段** = `[08:30,12:00]` ∪ `[13:30,17:30]`。
- **实际工时** = 打卡区间 `[clockIn, clockOut]` 与有效出勤段的重叠时长 − 请假时长(`durationMin`)。
- **迟到** = `clockIn > 08:30` 的部分（分钟）；**早退** = `clockOut < 17:30` 的部分（分钟）。
- **休息/节假日（且非补班）**：不计入应出勤；若有打卡记为加班（可选开关）。
- **公式（伪码）**：
  ```
  valid = overlap([ci,co],[08:30,12:00]) + overlap([ci,co],[13:30,17:30])
  workMinutes = max(0, valid - leaveMinutes)
  lateMin  = ci > 08:30 ? ci-08:30 : 0
  earlyMin= co < 17:30 ? 17:30-co : 0
  ```
- 日历/统计中的"工时"统一取自该公式，保证打卡→工时→报表口径一致。

## 五、当日聚合（任务/待办/反馈）映射

- **任务 / 待办**：现有对象均带 `createdAt`（app.js:159/1539/2147），"当日"默认按 **`createdAt` 的日期**匹配；若后续任务增加"计划日期/截止日期"字段，优先用该字段（设计预留 `planDate`/`dueDate`）。
- **反馈**：按 `feedback.createdAt` 日期匹配。
- **角色权限过滤**：点击当天显示的内容按 `RT_PERM` / 现有角色体系过滤——本人仅见自己数据；具备管理角色（如 `op_*`）可见团队数据。日历本人考勤始终可见；团队视图留接口（后续批次）。
- 聚合逻辑复用 `renderStats`（app.js:2828）按日期范围裁剪 `allTasks`，避免重复实现。

## 九、风险与注意

- **TAB 栏 5 个**：移动端顶部 TAB 需可横滑/压缩，避免拥挤（CSS `.tabs` 改为可滚动）。
- **节假日数据维护**：年度 JSON 需每年更新；补班/补假以官方发布为准，建议留管理入口（阶段0 后 `holidays` 集合）。
- **"当日"口径**：默认 `createdAt`；若业务需要"计划日/截止日"映射，需先给任务加日期字段（单列立项）。
- **午休是否计入**：默认不计入（12:00–13:30），若贵司计薪含午休，设置中可调，保持公式单一来源。
- **角色权限**：日历本人视图先行；团队/管理视图留接口，避免首版过度设计。
- **工时口径统一**：打卡→工时→报表必须共用第四节公式，杜绝三处各算各的。
- **默认落地页**：改 `switchView('home')` 后，确保首页渲染不依赖任务列表数据（可独立加载）。
